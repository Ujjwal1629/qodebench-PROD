                         CRITICAL ISSUES (MUST FIX)
================================================================================

1. DOUBLE-CHARGING VULNERABILITY (Issue #1)
   Location: /app/api/payments/verify-payment/route.ts (Lines 82-98)
            /supabase/migrations/033_payment_system.sql (Lines 36-79)
   
   Problem: No unique constraint on razorpay_payment_id
   Impact:  User could be charged 2x if verify-payment called twice
   
   Example Attack:
   - User pays once, gets charged
   - Network retry or user clicks again
   - Second subscription created for same payment
   - User has 2 active subscriptions
   - Both in database - FINANCIAL LOSS
   
   Risk Level: EXTREME - Revenue impact


2. RACE CONDITION IN PAYMENT PROCESSING (Issue #2)
   Location: /app/api/payments/verify-payment/route.ts
            /app/api/payments/webhook/route.ts (Lines 46-70)
   
   Problem: verify-payment and webhook can execute simultaneously
   Impact:  Inconsistent state between tables
   
   Scenario:
   - T1: verify-payment creates subscription
   - T2: webhook processes payment.captured
   - T3: webhook updates transaction
   - T4: profile updates from verify-payment
   - Result: Data corruption - tables out of sync
   
   Risk Level: EXTREME - Data integrity


3. WEBHOOK DUPLICATE PROCESSING (Issue #3)
   Location: /supabase/migrations/033_payment_system.sql (Lines 86-122)
   
   Problem: No unique constraint on razorpay_payment_id in payment_transactions
   Impact:  Webhook can be processed multiple times
   
   Details:
   - Razorpay retries webhooks
   - Each retry creates new transaction record
   - Multiple records for single payment
   - Audit trail becomes unreliable
   - Potential for multiple renewals
   
   Risk Level: EXTREME - Data consistency
